# Stack Change Control Workflow

1. Detect a proposed technology change.
2. Check STACK-DECISION.md.
3. If locked, stop silent modification.
4. Create STACK-CHANGE-REQUEST.md.
5. Explain reason and evidence.
6. Evaluate alternatives.
7. Evaluate migration risk.
8. Obtain approval.
9. Update architecture and stack decision.
10. Execute migration incrementally.
11. Verify functionality, visuals, SEO, accessibility, performance and deployment.
12. Record the decision.
